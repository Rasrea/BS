# 规范化开发拆分方案

结合CMMI规范与项目现状，本次做规范化开发拆分，明确智能体分工、环境隔离、模块边界、配套文档、管控规则，避免功能误删、模块互相干扰。

---

## 一、智能体划分（共7个，专人专域、职责隔离）

### 1. 项目总控智能体
统筹整体进度、版本规划、跨模块协调、代码合并/上线审批、规范落地、风险管控。
**产出**：版本计划、会议纪要、风险台账、审批记录。

### 2. CAD解析引擎智能体
负责DXF/DWG解析、图层处理、空间识别、墙/地/顶分层工程量、房间命名；
仅维护本模块代码，不改动AI、报价、前端逻辑。

### 3. 大模型视觉识别智能体
负责Ollama多模型调用、图片预处理、Prompt管理、结构化数据解析；
主导模型精度Benchmark评测，区分开发、评测、生产三套调用逻辑。

### 4. 后端业务&报价引擎智能体
负责API接口、任务状态机、三层门禁、数据库、工序库、计价规则、报价计算、Excel导出；
存量计价公式、基础报价逻辑严禁私自修改。

### 5. 前端交互智能体
负责Vue页面、文件上传、队列管理、数据展示、人工绑定、报价预览；
仅调用后端标准接口，不篡改业务规则。

### 6. 模板&配置智能体
负责报价模板、工序套餐、单价体系、系统参数、Excel模板导入与字段映射。

### 7. 测试&环境运维智能体
维护三套隔离环境、编写测试用例、全量回归测试、模型Benchmark评测、服务部署、日志排查、数据备份。

---

## 二、三大物理隔离环境

代码/数据库/数据完全分离。

### 1. 开发环境
日常编码、局部自测。新功能先在此开发，代码提交后走审核再流转。

### 2. 测试+Benchmark评测区

- **功能测试区**：全流程回归测试，每次迭代校验原有功能是否正常，防止误删
- **模型评测区**：使用固定标准数据集，统一指标对比各模型识别精度、速度；仅做实验评测，不承接正式业务

### 3. 正式运行区
用于演示、正式业务运行。仅测试通过后发布上线，线上功能变更必须走审批流程，数据库定时备份。

### 标准流转流程

```
开发环境编码 → 代码审核 → 部署测试区（功能回归+模型评测） → 测试通过 → 发布正式区
```

## 三、系统模块拆分

低耦合，仅接口调用，禁止跨模块改代码。

| 模块 | 说明 | 归属智能体 |
|------|------|-----------|
| 图纸解析模块 | DXF/DWG解析、空间识别、分层工程量 | ② CAD引擎 |
| AI视觉识别模块 | Ollama调用、Prompt管理、结构化解析 | ③ 视觉识别 |
| 后端核心服务模块 | API接口、任务状态机、门禁、数据库 | ④ 后端业务 |
| 报价&工序引擎模块 | 计价规则、工序库、Excel导出 | ④ 后端业务 |
| 前端交互模块 | Vue页面、上传、展示、绑定 | ⑤ 前端交互 |
| 模板&配置中心模块 | 报价模板、单价体系、参数管理 | ⑥ 模板配置 |

## 四、配套文档体系（CMMI要求，全流程可追溯）

| 类别 | 文档 |
|------|------|
| **需求类** | 项目需求说明书、迭代功能清单、用户操作手册 |
| **设计类** | 总体架构设计、数据库设计文档、API接口文档、算法/计算公式说明 |
| **开发类** | 编码规范、版本变更日志、配置文件说明 |
| **测试类** | 回归测试用例、专项测试用例、模型Benchmark评测报告、Bug台账 |
| **部署运维类** | 环境部署手册、运维手册、权限管控文档 |

---

## 五、核心管控规则

1. **存量功能保护**：已上线/已交付的存量功能禁止直接删除，如需调整必须提交变更申请，经总控审批
2. **模块边界严守**：各智能体仅允许修改自身负责模块，跨模块改动需沟通+同步文档
3. **发布四步流程**：每次版本发布必须完成 — 代码合并 → 全量回归测试 → 文档更新 → 审批上线，四步缺一不可
4. **业务基线保护**：CAD算量规则、报价计算公式、基础单价作为业务基线，修改需专项审批
5. **Benchmark公平性**：标准测试数据集固定，不得随意替换，保证评测公平性
