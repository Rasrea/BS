## 一、总纲：为什么需要智能体分工

### 1.1 核心理念

智能体 = 具备**单一定义域职责**、**独立执行能力**、**明确输入输出边界**的工作角色。

在 BuildSight 项目中，我们将复杂系统拆分为**8个智能体**，每个智能体只关注一个领域的工作。这种拆分的核心价值：

| 价值 | 说明 |
|------|------|
| **职责隔离** | 每个智能体不关心其他智能体的内部实现 |
| **可替换性** | 某个智能体可以独立升级、替换，不影响整体 |
| **并行开发** | 学生可以分组开发不同智能体，减少依赖 |
| **教学质量** | 每个智能体对应一门技术课（CAD、AI、数据库等） |
| **可溯源性** | 问题定位 → 直接找到责任智能体 |

## 三、智能体详解（按职责域）

### 3.1 🧑 刘天峰老师 — 总控与教学质量智能体

> **一句话定位**: 整个系统的"大脑"和"质量门禁"，负责把PRD/客户需求翻译成可执行的任务，把任务分派给对应智能体，并验收交付物质量。

#### 3.1.1 职责清单

| 职责 | 说明 | 教学意义 |
|------|------|---------|
| **任务分解** | 将模糊需求（如"能不能报价"）拆成可执行步骤（P0/P1/P2/P3） | 学生学如何做需求分析 |
| **优先级排序** | 🔴P0核心→🟠P1体验→🟡P2可选→🟢P3远期 | 学生学资源分配 |
| **质量验收** | 每项交付物必须经过实测，不验收不通过 | 学生学交付标准 |
| **风险预警** | 发现方案不可行时及时叫停并调整方向 | 学生学风险管理 |
| **教学评估** | 评估每个智能体输出是否达到教学目标 | 教学闭环 |

#### 3.1.2 工作方式

```
用户需求（语音/文字）
    │
    ▼
┌─────────────────────────────────────┐
│ 刘天峰老师                           │

    │
    ▼
```

|------|------|------|

### 3.2 🏗️ CAD解析智能体

> **一句话定位**: 把CAD图纸变成结构化数据——识别出每个房间叫什么、有多大、有什么门窗洞口。

#### 3.2.1 技术栈

| 项目 | 内容 |
|------|------|
| 核心库 | ezdxf (DXF解析) |
| 难点 | DXF是矢量格式，房间名文字和房间多边形可能不在一起 |
| 核心算法 | 双层贪婪匹配：大空间优先 + 多边形内优先 + 去重消费 |
| 兼容格式 | DXF（直接解析）、DWG（通过图片间接识别） |
| 不支持 | 非标准弧形墙、建筑信息模型(BIM) |

#### 3.2.2 关键代码

| 文件 | 行数 | 核心函数 | 职责 |
|------|:----:|---------|------|
| `cad_parser.py` | 574行 | `parse_cad_file()` / `_extract_spaces_with_names()` | DXF矢量解析 + 房间名匹配 |
| `deduct_rule.py` | 185行 | `apply_deductions()` | 门窗洞口扣减（4种类型） |

#### 3.2.3 核心流程

```
DXF/DWG文件
    │
    ▼
┌─────────────────────┐
│ 1. 格式检查          │
│    .dxf → ezdxf直接  │
│    .dwg → 图片识别   │
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ 2. 图层过滤          │ ← 只取 000-墙体1 图层
│    黑白名单           │ ← 过滤家具名/尺寸标注
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ 3. 空间提取           │
│    LWPOLYLINE实体     │ ← 只取闭合多边形
│    面积计算            │ ← polygon.area
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ 4. 文字提取           │
│    TEXT/MTEXT实体     │
│    plain_text()去格式码│
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ 5. 双层贪婪匹配       │ ← 核心算法
│    大空间优先 +        │
│    坐标关联 + 去重消费  │
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ 6. 输出结构化JSON     │
│    [{name, area,     │
│      dimensions,     │
│      deductions}]    │
└─────────────────────┘
```

#### 3.2.4 关键算法：双层贪婪匹配

这是本智能体最核心的技术难点，务必理解：

```python
# 伪代码示意
def match_names_to_spaces(spaces, texts):
    # 第一层：关键词标签
    keyword_texts = [t for t in texts if contains_room_keyword(t.text)]
    
    # 按面积从大到小排序
    spaces.sort(key=lambda s: s.area, reverse=True)
    
    for space in spaces:
        # 优先找多边形内的文字
        for text in keyword_texts:
            if text.coordinate is inside or touching space.polygon:
                space.name = text.text
                consume text  # 一个房间名只用一次
                break
        # 没找到再用最近邻（不设距离阈值！）
        if not space.name:
            nearest = min(keyword_texts, key=lambda t: distance(t, space.centroid))
            space.name = nearest.text
            consume nearest
    
    # 第二层：短文本回退（给未命名的）
    for space in unfilled_spaces:
        short_texts = [t for t in remaining_texts if is_short_cjk(t)]
        if short_texts:
            space.name = nearest(short_texts)
```

**⚠️ 关键陷阱**: 多户型大图里，房间名文字距离多边形质心最远可达28米。**不设距离阈值**，靠"贪婪匹配+去重消费"保证每个名只用一次。

### 3.3 🖼️ 视觉识别智能体

> **一句话定位**: 看懂装修效果图——识别出房间类型、墙面/地面/顶面分别用了什么材料、什么装修风格。

#### 3.3.1 技术栈

| 项目 | 内容 |
|------|------|
| 推理引擎 | Ollama（本地部署） |
| 视觉模型 | qwen2.5vl:latest（首选，50%准确率）/ llava:7b（备用） |
| 架构模式 | Harness 5阶段流水线 |
| 图像预处理 | 最长边1024px / JPEG85 / 去EXIF / RGBA→RGB |
| 透视裁剪 | 按高度拆分：顶面0-30% / 墙面25-75% / 地面60-100% |

#### 3.3.2 关键代码

| 文件 | 行数 | 职责 |
|------|:----:|------|
| `image_recognizer.py` | 40行 | 兼容层，委托给Harness |
| `image_preprocessor.py` | 100行 | 图片缩放/压缩/去EXIF |

#### 3.3.3 核心流程：Harness 5阶段流水线

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  全图推理  │ →  │  类型校验  │ →  │  规则校验  │ →  │  裁剪重试  │ →  │  输出     │
│(Inferrer) │    │(Validator)│    │(Validator)│    │(Retry)   │    │(Result)  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
                     ↑ 发现触发条件   ↑ 发现规则冲突
                     │
              ┌──────┴──────┐
              │ 透视裁剪分区  │
              │ ceiling 0-30%│
              │ wall  25-75% │
              │ floor 60-100%│
              └─────────────┘
```

**每阶段职责**:

| 阶段 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **推理** | 调用大模型识别全图 | 预处理后的图片 | 原始JSON（墙/地/顶材质） |
| **类型校验** | 检查字段是否在枚举列表内 | 模型原始输出 | 修正后的输出 + 警告 |
| **规则校验** | 检查材质-空间是否合理（如客厅顶≠铝扣板） | 类型校验后的输出 | 触发重试或返回结果 |
| **裁剪重试** | 裁剪有问题的区域，针对性重新推理 | 原始图片 + 触发条件 | 替换重试后的值 |
| **输出** | 格式化最终结果 | 所有阶段结果 | 结构化JSON + 重试日志 |

### 3.5 📊 报价系统智能体

> **一句话定位**: 有了房间面积和材料，算多少钱——基础价 + 材料差价 + 管理费 + 税费，输出格式规范的Excel报价单。

#### 3.5.1 技术栈

| `surface_breakdown.py` | 149行 | 墙面/地面/顶面分层算量 |

#### 3.5.3 四层报价公式

```
最终报价 = 基础价 + 材质差价 + 管理费 + 税费

其中：
  基础价 = 总面积 × 单位面积基础单价
  材质差价 = Σ(各空间材质差价)
  管理费 = (基础价 + 材质差价) × 管理费率(5%)
  税费   = (基础价 + 材质差价 + 管理费) × 税率(3%)
```

#### 3.5.4 分层工程量算法

```
地面面积  = CAD多边形面积
顶面面积  = 地面面积（标准层高）
墙面毛面积 = 近似周长 × 层高 × 周长系数
墙面净面积 = 毛面积 × (1 - 扣减比例)

其中：
  周长 ≈ 2 × (长 + 宽) × 周长系数(1.05)
  扣减比例：
    - 通用空间：15%
    - 厨卫空间：12%
    - 阳台空间：20%
```

| 数据融合 → DB | 报价JSON | `{total_price, items, trace}` | 总价>0 |
| DB → 前端 | 展示数据 | API JSON响应 | 统一格式 |
| 前端 → DB | 人工修正 | `{space_id, new_name, material}` | 操作日志记录 |

## 六、常见问题 FAQ

### Q1: 为什么要有8个智能体？3个不够吗？

**A**: 8个智能体对应8个独立的职责域和技术栈，目的是：
- **教学上**：一个智能体=一门课程（CAD=图形学，AI=深度学习，前端=Vue开发…）
- **工程上**：每个智能体可独立开发测试，不会相互阻塞
- **管理上**：问题出在哪个环节，直接找对应的智能体负责人

### Q2: CAD解析智能体为什么命名不完美（24个未命名）？

**A**: 不是能力问题，是数据问题。DXF中墙体用LINE线段绘制，没有闭合多边形。系统只能识别家具轮廓（92个）和真正的房间（82个已命名），剩余24个是"梁"等非房间区域。

### Q3: 视觉识别50%准确率够用吗？

**A**: 在L3人工绑定环节可以纠正。演示流程中：AI自动匹配70% → 人工修正30% → 最终100%准确。50%准确率是指12张GT严格匹配的比例，实际业务中通过同义词引擎+人工修正可以完全兜底。

### Q4: 刘天峰老师智能体和其他智能体什么关系？

**A**: 刘天峰老师是"总编"角色，其他智能体是"记者"。记者写稿（执行技术任务），总编决定写什么、什么时候交稿、改到什么时候算通过。刘天峰老师不替记者写稿，只做质量管理和任务分配。

### Q5: 这些智能体需要独立部署吗？

**A**: 不需要。8个智能体共享同一套Python进程 + 同一个SQLite数据库 + 同一个FastAPI服务。智能体是逻辑划分不是物理部署。教学演示时可以在同一台笔记本上全部运行。

### Q6: 如果我想复现这个项目，从哪个智能体开始？

**A**: 推荐顺序：**项目管理 (文档+API) → CAD解析 → 数据融合 → 报价 → 前端 → 视觉识别 → 系统检验**。先搭骨架再填内容。视觉识别最复杂放在后面，先用虚拟数据跑通全链路。

### Q7: 代码量7400行，我一个人能做完吗？

**A**: 能。本项目就是一个人（刘天峰老师带领一个AI助手）在6周内完成的。关键不是代码量，而是**严格的范围管理和优先级排序**——核心链路优先，非核心标记P1/P2后移。
