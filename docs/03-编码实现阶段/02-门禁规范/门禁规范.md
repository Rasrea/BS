# 门禁规范 v2.0

## 什么是门禁

门禁 = **在操作执行前做拦截检查**，不满足条件直接拒绝，阻止非法/违规操作进入系统。

超时熔断、前端按钮置灰这些是容错/体验机制，不是门禁，不应混为一谈。

---

## 三道真实门禁

### 第一道：混装门禁

**位置**：`backend/main.py` → `check_mixed_request()`

**作用**：禁止同一请求同时携带CAD + 图片

```python
def check_mixed_request(cad_file, image_file):
    if cad_file and image_file:
        raise HTTPException(409, "禁止混合请求")
```

**拦截**：`409 Conflict` — 必须分两次单独调用

---

### 第二道：文件门禁

**位置**：`backend/main.py` → `check_file_gate()`

**作用**：请求到达后、执行前，检查文件格式和大小

| 类型 | 允许格式 | 最大大小 |
|------|---------|---------|
| CAD | .dxf, .dwg | 120MB |
| 图片 | .jpg, .jpeg, .png, .webp, .bmp | 10MB |
| PDF | .pdf | 50MB |

**拦截**：`415 Unsupported Media Type` / `413 Payload Too Large`

---

### 第三道：状态机锁

**位置**：`backend/main.py` → `class TaskState`

**作用**：确保系统在空闲状态才能接受新任务，5种互斥状态：

```
idle ──→ cad_running ──→ idle
     ──→ ai_running  ──→ idle
     ──→ merge_running ──→ idle
     ──→ export_running ──→ idle
```

**规则**：
- 仅 `idle` 可接受新任务（`require_idle()`）
- 每种任务类型对应一种锁状态
- 异常退出通过 `task_state.reset()` 强制释放

**拦截**：`409 Conflict` — "系统当前有任务正在执行"

```python
async def require_idle(task_type):
    ok_flag, tid = await task_state.acquire(task_type)
    if not ok_flag:
        raise HTTPException(409, f"系统有任务正在执行（{task_state.state}）")
    return tid
```

## 非门禁的配套机制（仅供参考，不是门禁）

| 机制 | 分类 | 说明 |
|------|------|------|
| 前端按钮置灰 | 用户体验 | 任务中禁用按钮，防止重复提交 |
| 超时熔断 safe_run | 容错 | 任务超时后释放锁，避免卡死 |
| 队列串行 | 调度策略 | 多图逐张处理，不是拦截检查 |

---

## 门禁拦截统计

| 门禁 | 拦截条件 | 状态码 | 说明 |
|------|---------|--------|------|
| 混装门禁 | CAD+图片同请求 | 409 | 极少触发 |
| 文件门禁 | 格式/大小不合法 | 415/413 | 低频率 |
| 状态机锁 | 非idle时请求任务 | 409 | 中频率 |
