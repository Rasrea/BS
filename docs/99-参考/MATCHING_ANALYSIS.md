# 材质匹配率 57.5% 根因分析与优化方案

## 当前匹配率
- **匹配率**: 57.5% (61/106 个空间已匹配，45 个未匹配)

## 一、系统架构梳理

### 数据流
```
CAD图纸 → cad_parser.py → 106个空间名 (DB cad_analysis_results.space_name)
效果图  → vision_harness  → 5-14个空间类型+材质 (DB image_analysis_results.recognized_space)
                                     ↓
                  main.py /api/data_merge → space_synonyms.match_space_name(cad_name, ai_space)
                                     ↓
                          匹配成功 → CAD空间获得材质数据
                          匹配失败 → CAD空间材质为空
```

### 匹配引擎：`space_synonyms.py`
6层匹配策略：
1. 完全相等
2. 同义词映射后相等（SYNONYM_MAP）
3. 复合词拆分匹配（客餐厅 → [客厅, 餐厅]）
4. 包含关系匹配（CONTAINS_MAP: 生活阳台 → [阳台]）
5. 标准化后包含关系（子串匹配，≥2字符）
6. 单字符匹配（"客" → "客厅"）

### AI输出的空间类型（受Prompt约束，material_library.py第13行）
仅14种：`客厅、餐厅、主卧、次卧、儿童房、书房、玄关、走廊、阳台、厨房、卫生间、衣帽间、储物间、休闲区`

### CAD可能的空间名（cad_parser.py第142-165行）
50+种，包括：客厅、餐厅、主卧、次卧、卧室、厨房、客房、卫生间、厕所、浴室、阳台、书房、衣帽间、玄关、走廊、过道、储藏室、儿童房、老人房、客餐厅、主卫、次卫、公卫、家政、储物、多功能、棋牌、影音、门厅、西厨、中厨、阳光房、茶室、棋牌室、影音室、健身房、瑜伽、保姆房、工人房、杂物间、设备间、入户花园、观景台、露台、花园、北次卧、南次卧、东次卧、西次卧、北卧、南卧、东卧、西卧、开放式厨房、大厅、中厅、小厅、休息室、娱乐室、活动室、电梯厅、电梯间、前室等

## 二、根因分析

### 根因1：AI输出空间类型仅14种，CAD有50+种（预测占未匹配的40%，约18个空间）

CAD中大量空间类型在AI输出列表中没有对应项。这些CAD空间完全无法匹配到任何AI空间类型：

**无法映射的空间**（AI完全不输出）：
| CAD空间 | 当前匹配情况 | 根因 |
|---------|-------------|------|
| 露台 | ❌ 无法匹配 | AI不输出"露台"，SYNONYM_MAP无"露台→阳台"映射，CONTAINS_MAP无"露台→阳台" |
| 庭院/花园 | ❌ 无法匹配 | AI不输出"庭院/花园" |
| 车库 | ❌ 无法匹配 | AI不输出"车库" |
| 设备间/设备阳台/空调机位 | ❌ 无法匹配 | AI不输出"设备间" |
| 电梯间/电梯厅 | ❌ 无法匹配 | AI不输出"电梯间" |
| 楼梯间 | ❌ 无法匹配 | AI不输出"楼梯间" |
| 茶室/棋牌室/影音室/健身房 | ❌ 无法匹配 | AI不输出这些类型 |
| 保姆房/工人房 | ❌ 无法匹配 | AI不输出这些类型 |
| 家政间/杂物间 | ❌ 无法匹配 | AI不输出"家政间" |
| 多功能房 | ❌ 无法匹配 | AI不输出"多功能房" |

### 根因2：SYNONYM_MAP缺少关键同义词映射（预测占未匹配的25%，约11个空间）

| CAD/AI名称 | 当前行为 | 预期行为 | 应如何修复 |
|-----------|---------|---------|-----------|
| AI输出"卧室"(无前綴) | normalize返回"卧室"(无映射)，CAD"主卧"不匹配"卧室" | 应匹配"次卧"(安全降级) | 添加"卧室"→"次卧"到SYNONYM_MAP |
| AI输出"大厅" | normalize返回"大厅"(无映射) | 应匹配"客厅" | 添加"大厅"→"客厅"到SYNONYM_MAP |
| AI输出"用餐区" | normalize返回"用餐区"(无映射) | 应匹配"餐厅" | 添加"用餐区"→"餐厅"到SYNONYM_MAP |
| AI输出"厨房区" | normalize返回"厨房区"(无映射) | 应匹配"厨房" | 添加"厨房区"→"厨房"到SYNONYM_MAP |
| AI输出"客卧" | normalize返回"客卧"(无映射) | 应匹配"次卧" | 添加"客卧"→"次卧"到SYNONYM_MAP |
| AI输出"休息区" | normalize返回"休息区"(无映射) | 应匹配"休闲区" | 添加"休息区"→"休闲区"到SYNONYM_MAP |
| AI输出"起居室" | 已有"起居室"→"客厅" | ✅ 正常 | — |
| CAD"露台" → AI"阳台" | 无映射 | 露台是阳台的一种 | 添加CONTAINS_MAP["露台"]=["阳台"] |
| CAD"庭院" → AI"阳台"或其他 | 无映射 | 无合理映射 | 需AI支持或人工绑定 |
| CAD"西厨" → AI"厨房" | CONTAINS_MAP["西厨"]=[] 显式设为不匹配 | 业务上西厨≠厨房，但为获取材质应允许 | 或将CONTAINS_MAP["西厨"]=["厨房"] |

### 根因3：AI模型输出不稳定 — 可能输出预期外的空间名（预测占未匹配的15%，约7个空间）

不同模型（llava:7b vs qwen2.5:7b）输出差异大：
- **llava:7b**: 倾向于输出"卧室"（无前綴）
- **qwen2.5:7b**: 倾向于输出"主卧"、"次卧"（带前綴）

即使约束到14种类型，模型仍可能输出：
- "卧室"（而非"主卧"或"次卧"）
- "大厅"（而非"客厅"）
- "私人空间"等编造类型

根因3.1：Prompt约束词虽然去掉了"卧室"，但模型依然输出"卧室"
根因3.2：AI对主卧/次卧的区分能力有限，视觉上难以区分

### 根因4：不同AI图片的重叠空间名冲突（预测占未匹配的10%，约5个空间）

data_merge端代码（main.py第709行）：
```python
if space not in ai_material_index or img["id"] > ai_material_index[space].get("image_id", 0):
    ai_material_index[space] = {...}
```

仅取"最新"识别的结果作为该空间类型的材质。如果有2张"客厅"图片，后识别的覆盖前者。但如果AI对同一CAD空间的不同图片识别出不同名称（如一张"客厅"、另一张"起居室"），则`ai_material_index`中会同时存在"客厅"和"起居室"两个条目，这对匹配是有利的（多了一个候选）。

但如果一张图识别为"客厅"，另一张被遮挡的图识别为"卧室"，同一个CAD"客厅"只能匹配到一个。

### 根因5：缺少相似度/模糊匹配（预测占未匹配的5%，约2个空间）

当前系统完全没有编辑距离（Levenshtein）或拼音相似度匹配：
- AI输出"主莴"（模型幻觉/typo）→ 完全不匹配
- AI输出"起局市"（garbled）→ 完全不匹配
- CAD"洗手台" → AI"洗手盆" → match_space_name("洗手台","洗手盆"): 两者都正常化到标准名。norm("洗手台")="洗手台", norm("洗手盆")="洗手台"！是的，因为"洗手盆"→"洗手台"在SYNONYM_MAP中（第162行）。所以这个实际上是OK的。

### 根因6（次要）：fusion_validator.py存在独立的、不一致的匹配系统（非当前问题源头但属维护隐患）

fusion_validator.py的ROOM_TYPE_ALIASES与space_synonyms.py的SYNONYM_MAP不一致：
- fusion: "主卫"→"卫生间"（降级）
- synom: "主卫"→"主卫"（保持）

当前data_merge未使用fusion_validator的匹配逻辑，但未来如果有人用`merge_dxf_and_vl`函数会得到不同结果。

## 四、优化方案（按收益/成本排序）

### 方案1：扩充SYNONYM_MAP ✅ 高收益低成本（预期+15%~+20%，约7-9个空间）

在`space_synonyms.py`中添加缺失的关键映射：

```python
SYNONYM_MAP.update({

    "卧室": "次卧",           # AI常输出"卧室"（无主/次），安全降级为次卧
    
    # === 修复AI输出的大厅类名 ===
    "大厅": "客厅",           # AI可能会输出"大厅"
    "大堂": "客厅",
    "起居室": "客厅",         # 已有，确认无遗漏
    "living": "客厅",         # 可作为"living room"的简写
    
    # === 修复AI输出的用餐区 ===
    "用餐区": "餐厅",
    "就餐区": "餐厅",
    
    # === 修复AI输出的厨房变异 ===
    "厨房区": "厨房",
    
    # === 修复AI输出客卧类 ===
    "客卧": "次卧",
    
    # === 其他常见变异 ===
    "休息区": "休闲区",
    "休息室": "休闲区",
    "活动室": "休闲区",
    "娱乐室": "休闲区",
    "多功能室": "休闲区",
    "多功能房": "休闲区",
    
    # === 卧室数字编号 ===
    "卧室1": "次卧",
    "卧室2": "次卧",
    "卧室3": "次卧",
})
```

**成本**: 修改1个文件，10行代码
**收益**: 预计提升约7-9个空间的匹配率

### 方案3：扩充AI Prompt中的空间类型列表 ✅ 中等收益中等成本（预期+10%，约4-5个空间）

修改`material_library.py`第13行：
```python
# 当前：
SPACE_TYPES = "客厅、餐厅、主卧、次卧、儿童房、书房、玄关、走廊、阳台、厨房、卫生间、衣帽间、储物间、休闲区"

SPACE_TYPES = "客厅、餐厅、主卧、次卧、儿童房、书房、玄关、走廊、阳台、厨房、卫生间、衣帽间、储物间、休闲区、露台、庭院、花园、车库、设备间、电梯间、楼梯间、老人房、阳光房、入户花园、生活阳台、茶室、棋牌室、影音室、健身房、保姆房"
```

同时必须在`SPACE_MATERIAL_RULES`中添加对应空间类型的材质规则，否则Validator会报警。

**成本**: 修改2个文件（material_library.py + space_synonyms.py），重新跑一遍AI识别需要时间
**收益**: 预计提升约4-5个空间的匹配率

### 方案4：AI结果后处理 — 模型输出归一化 ⚠️ 中等收益中等成本（预期+5%~+10%，约2-4个空间）

在`main.py`的data_merge中，在存入`ai_material_index`前将所有AI空间名先通过`space_synonyms.normalize_name()`归一化：

```python
# 当前（第699行）：
space = img.get("recognized_space", "").strip()

# 优化后：
raw_space = img.get("recognized_space", "").strip()
space = space_synonyms.normalize_name(raw_space) or raw_space
```

这样AI输出的"卧室"会自动变为"次卧"，"起居室"变为"客厅"。

**注意**: `normalize_name`的弱匹配（key in name）可能导致"淋浴"→"淋浴房"等副效应，需全面测试。

**成本**: 修改2行代码
**收益**: 预计提升约2-4个空间的匹配率

### 方案5：添加模糊匹配降级策略 ⚠️ 中等收益中等成本（预期+5%，约2个空间）

在`_match_impl`的最后（策略6之后）添加Levenshtein距离降级：

```python
# 策略7：编辑距离匹配（作为最后降级）
if len(cad_name) >= 2 and len(ai_name) >= 2:
    # 拼音/字形相似度
    # 先尝试公共子串 > 60%
    common = len(set(cad_name) & set(ai_name))
    if common / max(len(set(cad_name)), len(set(ai_name))) >= 0.6:
        return True
```

或使用更精确的编辑距离（需要引入`editdistance`或`Levenshtein`包）。

**成本**: 需要引入依赖库或手写算法
**收益**: 边缘情况，约2个空间

### 方案6：自动生成"最佳匹配"建议 ✅ 高收益低成本（预期+5%~+10%，约2-4个空间）

对无法匹配的CAD空间，按`get_matched_spaces()`返回的候选列表，自动勾选第一个非空候选作为"自动建议匹配"：

```
未匹配CAD: "露台"
get_matched_spaces("露台") → ["露台"]  (当前无映射)
若增加CONTAINS_MAP["露台"]=["阳台"]后：
get_matched_spaces("露台") → ["露台", "阳台"]
→ 自动建议匹配到"阳台"（若有AI识别的阳台材质）
```

配合方案2，大量未匹配空间可自动建议匹配。
