# DXF 识别逻辑重写计划

## 1. 目标与边界

第一阶段只承诺识别具有明确闭合空间边界的 DXF，不承诺从任意施工图中自动恢复房间。

核心目标：

- 从矢量几何计算可解释、可复核的房间面积。
- 宁可返回“无法确认”，也不生成看似精确的估算面积。
- 每个空间携带边界来源、名称来源、置信度证据和警告。
- 只有达到报价准入条件的空间才能进入 `main.py` 的面积汇总。

暂不处理：

- 依靠标签间距和默认尺寸猜测房间面积。
- 任意墙线图纸的完整空间重建。
- 使用视觉模型直接计算精确面积。

## 2. 迁移策略

保留以下兼容面：

- `cad_parser.py` 继续作为 DXF、DWG、PDF、图片的分发入口。
- 保留 `_parse_dxf(file_path: str) -> dict` 函数签名。
- 返回结果继续包含 `spaces`、`area_sqm` 和 `dimensions`。
- `main.py` 现有调用方先不需要同步大改。

迁移期间保留旧实现用于样图对比：

```python
def _parse_dxf(file_path: str) -> dict:
    return parse_dxf_v2(file_path)


def _parse_dxf_legacy(file_path: str) -> dict:
    ...
```

新版达到验收标准后删除旧实现和 `_calc_rooms_from_lines()` 估算逻辑。

## 3. 推荐模块结构

```text
backend/
  cad_parser.py                 # 文件类型分发与兼容入口
  dxf_parser/
    __init__.py
    parser.py                   # 组织完整流水线
    extractor.py                # 单位、图层、块和图元提取
    geometry.py                 # 曲线离散化、多边形构造与修复
    candidates.py               # 空间候选评分、去重与冲突处理
    labels.py                   # 文本清洗、分类与空间关联
    quality.py                  # 置信度、警告和报价准入判定
```

初次实现也可以先合并为一个 `dxf_parser.py`，待逻辑稳定后再拆包。

## 4. V2 处理流水线

### 4.1 读取与标准化

1. 使用 `ezdxf.readfile()` 读取文件并返回可诊断错误。
2. 读取 `$INSUNITS`，建立“图纸单位到毫米”的换算因子。
3. 提取模型空间范围，识别异常坐标和超大图框。
4. 展开 `INSERT/BLOCK`，应用平移、旋转和缩放变换。
5. 将 OCS 坐标统一转换为 WCS/二维工作坐标。

无法确认单位时，不直接假定为毫米；返回 `unit_unknown` 警告并禁止自动报价。

### 4.2 图层角色推断

先对图层名进行去空格、大小写和分隔符归一化，再推断角色：

- `room_boundary`
- `wall`
- `door`
- `window`
- `room_text`
- `dimension`
- `furniture`
- `unknown`

角色依据包括图层名称关键词、实体类型分布和项目级配置，不使用唯一固定白名单。

### 4.3 闭合边界候选生成

第一阶段支持：

- 闭合 `LWPOLYLINE`
- 闭合二维 `POLYLINE`
- `HATCH` 的外边界与洞

几何处理要求：

- 将 `bulge` 和 `ARC` 按可配置误差离散为线段。
- 删除连续重复点和过短边。
- 使用 `is_valid` 检查自交等拓扑问题。
- 使用 `make_valid` 或受控方式修复，并记录修复警告。
- 保留实体 handle、原图层和边界类型，确保结果可追溯。

### 4.4 候选清洗

候选不能仅凭面积阈值认定为房间。每个候选收集以下证据：

- 是否来自明确房间边界图层。
- 内部是否存在可信房间名称。
- 是否包含多个其他高质量房间候选。
- 是否与其他候选近似重合。
- 是否呈现极细长、极小或异常巨大的形状。
- 是否位于图框、标题栏或说明区域。

清洗规则：

- 合并或淘汰近似重复轮廓。
- 对嵌套轮廓保留关系，不用面积排序直接消费标签。
- 对大面积包含多个已命名房间的轮廓，优先判断为户型外框。
- 所有面积范围都在单位标准化后应用，并允许配置。

### 4.5 房间文字关联

文字处理对象包括 `TEXT` 和 `MTEXT`：

1. 清除换行、格式控制符和多余空格。
2. 分类为房间名、尺寸文字、材料说明、编号或未知文字。
3. 自动命名只使用位于空间内部或边界容差内的房间名候选。
4. 多个候选同时位于内部时，综合图层、词典、字高和距空间代表点的距离评分。
5. 外部最近文字只作为诊断候选，不直接绑定。

未找到可信标签时输出 `name: null` 或“未命名空间”，不得跨区域强制命名。

### 4.6 几何量计算

- `area_sqm`：由标准化后的多边形面积计算。
- `perimeter_m`：使用真实边界长度计算。
- `dimensions`：规则空间可使用最小旋转矩形给出几何长宽。
- 异形空间应标记 `irregular_shape`，不把包围盒解释为建筑开间和进深。
- 输出 `area_type` 和 `geometry_source`，明确面积口径及来源。

`DIMENSION` 只用于核验计算值。附近标注与几何值一致时提高置信度，不一致时增加警告。

## 5. 置信度与报价准入

禁止使用固定置信度。建议按证据评分并保留评分明细：

```json
{
  "name": "主卧",
  "area_sqm": 15.62,
  "area_type": "net_floor_area",
  "geometry_source": "closed_lwpolyline",
  "name_source": "internal_text",
  "confidence": 0.94,
  "evidence": [
    "valid_closed_boundary",
    "room_label_inside",
    "unit_confirmed"
  ],
  "warnings": []
}
```

建议质量等级：

- A：单位、边界和名称均可信，可以自动计入报价。
- B：几何可信但名称或轮廓关系存在轻微疑问，需要用户确认。
- C：仅为空间候选，不参与报价。
- D：无法构造可信空间。

`main.py` 应只汇总满足报价准入条件的空间，并单独返回待确认空间。

## 6. 墙线型 DXF 后续计划

墙线型识别作为第二阶段单独开发，不继续调整旧版经验系数。目标流程：

```text
墙线分类
  -> 曲线离散化
  -> 端点吸附
  -> 共线线段合并
  -> 小断点修复
  -> 门洞识别或临时封闭
  -> unary_union / polygonize
  -> 空间候选清洗
  -> 内部文字关联
  -> 房间邻接关系构建
```

旧版 `_calc_rooms_from_lines()` 存在以下根本问题，应在 V2 接管后移除：

- 提取的墙线 `segments` 没有参与最终边界构造。
- 用房间标签坐标分行并分配宽度。
- 使用全局最大尺寸作为建筑宽度。
- 缺少尺寸时默认高度为 3000 mm。
- 所有空间都被假定为矩形。

## 7. 测试数据与验收

建立小型标注数据集，每张 DXF 保存人工确认的房间名称、面积和边界来源。样本至少包括：

- 标准闭合 `LWPOLYLINE` 户型。
- 米、厘米和毫米三种单位。
- 带弧形边界的房间。
- `HATCH` 表达房间或墙体的图纸。
- 房间边界和文字位于块中的图纸。
- 重复、嵌套和部分重叠轮廓。
- 一个空间多个文字、一个户型多个同名空间。
- 图框、家具和吊顶轮廓干扰明显的图纸。
- 没有闭合边界的墙线型图纸，用于验证系统不会伪造面积。

第一阶段验收建议：

- A 级空间面积相对误差不超过 2%。
- A 级房间名称准确率不低于 95%。
- 外框、家具和吊顶被误识别为 A 级房间的数量为 0。
- 单位未知、边界修复失败或存在高重叠冲突时禁止自动报价。
- 同一输入重复解析结果稳定一致。

## 8. 实施顺序

1. 建立 DXF 样图清单和人工真值 JSON。
2. 实现单位、图层、实体和块的统一提取层。
3. 实现闭合边界构造、修复、去重和嵌套分析。
4. 实现房间文字分类与严格内部关联。
5. 实现证据评分、质量等级和报价准入。
6. 接入 `_parse_dxf()` 并进行新旧结果对比。
7. 修改 `main.py`，只汇总准入空间。
8. 删除旧墙线估算逻辑。
9. 单独立项实现墙线拓扑重建。
